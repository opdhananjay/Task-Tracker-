=========================================================
DEVOPS TASK TRACKER – COMPLETE SYSTEM FLOW
=========================================================

PROJECT OVERVIEW
---------------------------------------------------------

DevOps Task Tracker is a role-based task, testing,
and issue management system designed for software teams.

The system helps organizations manage:

- Team members
- Development tasks
- Testing workflows
- Bug/Issue tracking
- Team productivity
- Development lifecycle tracking

The platform supports:

- Admin
- Manager
- Team Lead
- Developer
- Tester

=========================================================
1. COMPANY / ADMIN REGISTRATION FLOW
=========================================================

A company/admin visits the platform.

Admin registers with:

- Company Name
- Admin Name
- Email
- Password
- Confirm Password

System automatically creates:

- Company Workspace
- Admin Account
- Organization Profile

Admin becomes top-level user of that company workspace.

=========================================================
2. ADMIN LOGIN FLOW
=========================================================

Admin logs in using:

- Email
- Password

System validates:

- Credentials
- Company mapping
- User status

After successful login:

- Admin Dashboard loads

=========================================================
3. ORGANIZATION / COMPANY MANAGEMENT
=========================================================

Each registered company has its own isolated workspace.

Organization contains:

- Organization Name
- Email
- Phone Number
- Address
- Organization Type
- Created By
- Created Date

All users and tasks belong to organization.

=========================================================
4. USER MANAGEMENT FLOW
=========================================================

Admin can create users inside organization.

Available Roles:

- Manager
- Team Lead
- Developer
- Tester

User fields:

- First Name
- Last Name
- Email
- Password
- Role
- Department
- Phone Number
- Employee ID
- OrganizationId

Every user is linked to organization.

=========================================================
5. USER LOGIN FLOW
=========================================================

Users login using:

- Email
- Password

System validates:

- User exists
- Password valid
- Role valid
- Organization mapping
- User active status

After login:

- Role-based dashboard loads

=========================================================
6. ROLE-BASED DASHBOARD FLOW
=========================================================

---------------------------------------------------------
ADMIN DASHBOARD
---------------------------------------------------------

Admin can:

- Create users
- Manage all users
- Manage organization settings
- View all tasks
- View all issues
- View analytics/reports

---------------------------------------------------------
MANAGER DASHBOARD
---------------------------------------------------------

Manager can:

- Create tasks
- Update tasks
- Monitor teams
- View reports
- View issues
- Convert issues to tasks

---------------------------------------------------------
TEAM LEAD DASHBOARD
---------------------------------------------------------

Team Lead can:

- Create tasks
- Assign developers/testers
- Track progress
- Monitor pending tasks
- Review development/testing workflow

---------------------------------------------------------
DEVELOPER DASHBOARD
---------------------------------------------------------

Developer can:

- View assigned tasks
- Start tasks
- Update task progress
- Submit development notes
- Submit unit testing details

---------------------------------------------------------
TESTER DASHBOARD
---------------------------------------------------------

Tester handles BOTH:

1. Testing Responsibilities
2. Support / Issue Reporting Responsibilities

Tester can:

- Create issues
- Report bugs
- View testing queue
- Approve tasks
- Reject tasks
- Add testing comments

=========================================================
7. TASK MANAGEMENT FLOW
=========================================================

Task can be created by:

- Admin
- Manager
- Team Lead

Task fields:

- Title
- Description
- Task Type
- Developer
- Tester
- Priority
- Status
- Start DateTime
- Due DateTime
- Unit Testing Status
- Acceptance Criteria
- Issue Reference (optional)
- OrganizationId
- CreatedBy

=========================================================
8. TASK STATUS FLOW
=========================================================

Task lifecycle:

Not Started
→ In Progress
→ Dev Done
→ Testing
→ Completed

If tester rejects:

Testing
→ In Progress

=========================================================
9. DEVELOPER WORKFLOW
=========================================================

Developer receives assigned task.

Developer actions:

- Start task
- Update progress
- Complete development
- Add development notes
- Submit unit testing details

Developer updates:

Not Started
→ In Progress
→ Dev Done

=========================================================
10. UNIT TESTING FLOW
=========================================================

Developer submits:

- Test cases written
- Test cases executed
- Test results
- Unit testing notes

Unit testing status:

- Pending
- Completed
- Failed

Task then moves to testing stage.

=========================================================
11. TESTER VALIDATION FLOW
=========================================================

Tester receives task for validation.

Tester verifies:

- Acceptance criteria
- Functionality
- Unit testing details
- Development quality

Tester actions:

Approve:
Testing → Completed

Reject:
Testing → In Progress

Tester can add:

- Bug comments
- Testing notes
- Rejection reason

=========================================================
12. ISSUE MANAGEMENT FLOW (FUTURE MODULE)
=========================================================

(Current focus remains Task Tracker module.
Issue module will be developed after task workflow.)

---------------------------------------------------------
WHY ISSUE MANAGEMENT?
---------------------------------------------------------

Testers/support teams may find:

- Bugs
- UI issues
- API failures
- Performance problems
- Feature requests

Instead of manual communication,
issues will be tracked in system.

---------------------------------------------------------
ISSUE CREATION FLOW
---------------------------------------------------------

Tester creates issue with:

- Issue Title
- Description
- Issue Type
- Priority
- Screenshot/File (optional)
- Status
- OrganizationId

Issue Types:

- Bug
- Enhancement
- Feature Request
- Support Issue

Issue Status:

- Open
- Converted
- Closed
- Rejected

=========================================================
13. ISSUE TO TASK CONVERSION FLOW
=========================================================

Manager/Team Lead reviews issue.

If development required:

Issue → Convert To Task

Task can reference:

IssueId

Flow:

Tester reports issue
→ Manager reviews
→ Convert to task
→ Developer fixes
→ Tester validates
→ Issue closes
